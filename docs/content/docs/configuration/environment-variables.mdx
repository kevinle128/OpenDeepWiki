# 环境变量

本页提供 OpenDeepWiki 支持的所有环境变量的完整参考。变量可以通过 Docker Compose `environment` 部分、项目根目录的 `.env` 文件或系统环境变量设置。

<Callout type="info">
  环境变量优先于 `appsettings.json` 中的值。
</Callout>

## 数据库

| 变量 | 必需 | 默认值 | 描述 |
|---|---|---|---|
| `DB_TYPE` | 否 | `sqlite` | 数据库后端类型。支持的值：`sqlite`、`postgresql`（等价于 `Database__Type`） |
| `CONNECTION_STRING` | 否 | `Data Source=/data/opendeepwiki.db` | 数据库连接字符串（等价于 `ConnectionStrings__Default`） |

对于 PostgreSQL，使用 Npgsql 连接字符串格式：

```
Host=<host>;Port=5432;Database=opendeepwiki;Username=<user>;Password=<password>
```

详见 [数据库配置](/docs/deployment/database)。

## JWT 认证

| 变量 | 必需 | 默认值 | 描述 |
|---|---|---|---|
| `JWT_SECRET_KEY` | 是（生产环境） | 内置开发密钥 | 用于 JWT 令牌的 HMAC-SHA256 签名密钥。生产环境必须更改，且长度至少 32 个 UTF-8 字节、不得为内置默认值，否则应用将拒绝启动 |

<Callout type="warn">
  默认 JWT 密钥仅用于开发。在生产环境中始终设置强大、唯一的 `JWT_SECRET_KEY`。
</Callout>

JWT 发行者、受众和过期时间通过 `appsettings.json` 的 `Jwt` 部分配置：

```json
{
  "Jwt": {
    "Issuer": "OpenDeepWiki",
    "Audience": "OpenDeepWiki",
    "ExpirationMinutes": 1440
  }
}
```

## Git connection secrets and provider access

A shared Git connection stores one provider token. The application encrypts the token with ASP.NET Core Data Protection
before it writes it to the database. The keys that encrypt it are kept in a key ring directory, outside the database.
See [Shared Git connections](/docs/deployment/docker-compose#git-connection-secrets) for backup and restore.

| Variable | Required | Default | Description |
|---|---|---|---|
| `DataProtection__KeyRingPath` | Yes (Production) | — | Directory of the Data Protection key ring (configuration key `DataProtection:KeyRingPath`). In Production the application refuses to start without it and exits with code 1. The directory must be persistent and must be backed up with the database. If the key ring is lost, every saved Git connection token becomes unreadable and must be replaced. The key files are plain XML protected by file permissions only. No certificate or key-management service option is implemented |
| `GitProviders__AllowedPrivateHosts__0` | No | empty | Exact host name of a self-hosted GitLab server that may resolve to a private or loopback address. Add more entries with `__1`, `__2`, and so on. Configuration key `GitProviders:AllowedPrivateHosts` |
| `GitProviders__AllowedPrivateCidrs__0` | No | empty | CIDR range, for example `10.20.0.0/16`, in which a self-hosted GitLab server address may fall. A range that cannot be parsed stops the application at startup. Configuration key `GitProviders:AllowedPrivateCidrs` |
| `GitProviders__RequestTimeoutSeconds` | No | `15` | Time limit of one provider request, from 1 to 120 seconds. A value outside this range stops the application at startup |

Rules of the address policy for self-hosted GitLab:

- The server URL must be an HTTPS origin: no user information, path, query, or fragment.
- A server on a public address works without any allowlist entry.
- A server on a private or loopback address works only when its exact host name or its address range is in the allowlist.
- Link-local, cloud metadata, unspecified, multicast, and reserved addresses are always blocked, even when they are in the allowlist.
- If a host name resolves to more than one address, one blocked address rejects the request.

<Callout type="info">
  Earlier versions ignored `JWT_SECRET_KEY` and signed tokens with the built-in key. This version uses `JWT_SECRET_KEY`.
  On the first start after the upgrade, every existing session becomes invalid and each user signs in again once.
</Callout>

## AI 服务（聊天）

这些变量配置用于聊天和对话功能的 AI 服务。

| 变量 | 必需 | 默认值 | 描述 |
|---|---|---|---|
| `CHAT_API_KEY` | 是 | — | 聊天 AI 服务的 API 密钥 |
| `ENDPOINT` | 是 | `https://api.routin.ai/v1`（内置默认） | 聊天 AI 服务端点 URL |
| `CHAT_REQUEST_TYPE` | 否 | `OpenAI` | AI 提供商类型：`OpenAI`、`AzureOpenAI`、`Anthropic`、`OpenAIResponses`、`DeepSeekOpenAI` |

这些变量配置用于生成文档目录（目录）结构的 AI 模型。

## Wiki 生成 — 目录

这些变量配置用于生成文档目录（目录）结构的 AI 模型。

| 变量 | 必需 | 默认值 | 描述 |
|---|---|---|---|
| `WIKI_CATALOG_MODEL` | 否 | `gpt-4o` | 目录生成的模型名称 |
| `WIKI_CATALOG_ENDPOINT` | 是 | — | 目录生成的 API 端点 |
| `WIKI_CATALOG_API_KEY` | 是 | — | 目录生成的 API 密钥 |
| `WIKI_CATALOG_REQUEST_TYPE` | 否 | `OpenAI` | 提供商类型：`OpenAI`、`AzureOpenAI`、`Anthropic`、`OpenAIResponses`、`DeepSeekOpenAI` |

## Wiki 生成 — 内容

这些变量配置用于生成文档页面内容的 AI 模型。

| 变量 | 必需 | 默认值 | 描述 |
|---|---|---|---|
| `WIKI_CONTENT_MODEL` | 否 | `gpt-4o` | 内容生成的模型名称 |
| `WIKI_CONTENT_ENDPOINT` | 是 | — | 内容生成的 API 端点 |
| `WIKI_CONTENT_API_KEY` | 是 | — | 内容生成的 API 密钥 |
| `WIKI_CONTENT_REQUEST_TYPE` | 否 | `OpenAI` | 提供商类型：`OpenAI`、`AzureOpenAI`、`Anthropic`、`OpenAIResponses`、`DeepSeekOpenAI` |

## Wiki 生成 — 翻译（可选）

翻译配置是可选的。如果未设置，系统将回退到 wiki 内容配置。

| 变量 | 必需 | 默认值 | 描述 |
|---|---|---|---|
| `WIKI_TRANSLATION_MODEL` | 否 | 与 `WIKI_CONTENT_MODEL` 相同 | 翻译的模型名称 |
| `WIKI_TRANSLATION_ENDPOINT` | 否 | 与 `WIKI_CONTENT_ENDPOINT` 相同 | 翻译的 API 端点 |
| `WIKI_TRANSLATION_API_KEY` | 否 | 与 `WIKI_CONTENT_API_KEY` 相同 | 翻译的 API 密钥 |
| `WIKI_TRANSLATION_REQUEST_TYPE` | 否 | 与 `WIKI_CONTENT_REQUEST_TYPE` 相同 | 提供商类型 |

## Wiki 生成 — 常规

| 变量 | 必需 | 默认值 | 描述 |
|---|---|---|---|
| `WIKI_PARALLEL_COUNT` | 否 | `5` | 并行文档生成任务数。更高的值加快生成但使用更多资源 |
| `WIKI_MAX_CONCURRENT_GENERATIONS` | 否 | `1` | 整个集群同时进行仓库 Wiki 生成的上限。多实例共享这个配额 |
| `WIKI_LANGUAGES` | 否 | `en,vi` | 多语言 wiki 生成的目标语言逗号分隔列表 |
| `REPOSITORIES_DIRECTORY` | 否 | `/data` | 用于存储克隆仓库文件的目录 |
| `WIKI_MAX_OUTPUT_TOKENS` | 否 | `32000` | 单次 AI 生成的最大输出 Token 数，防止回复过长 |
| `WIKI_DOCUMENT_GENERATION_TIMEOUT_MINUTES` | 否 | `60` | 单篇文档生成任务的超时时间（分钟） |
| `WIKI_TRANSLATION_TIMEOUT_MINUTES` | 否 | `45` | 翻译任务允许的最长执行时间（分钟） |
| `WIKI_TITLE_TRANSLATION_TIMEOUT_MINUTES` | 否 | `2` | 目录标题翻译的超时时间（分钟） |
| `WIKI_README_MAX_LENGTH` | 否 | `4000` | README 摘要在生成前的最大字符长度 |
| `WIKI_DIRECTORY_TREE_MAX_DEPTH` | 否 | `2` | 扫描仓库目录结构时的最大深度 |
| `WIKI_MAX_RETRY_ATTEMPTS` | 否 | `3` | 调用 AI 接口失败时的最大重试次数 |
| `WIKI_RETRY_DELAY_MS` | 否 | `1000` | AI 调用重试之间的等待时间（毫秒） |
| `WIKI_PROMPTS_DIRECTORY` | 否 | `prompts` | 自定义 wiki 生成提示模板所在目录 |

<Callout type="info">
  Saved Wiki runtime settings take priority over environment defaults; see `src/OpenDeepWiki/Program.cs` (`SystemSettingDefaults.ApplyToWikiGeneratorOptions`).
  Use **Admin Settings → AI** to change `WIKI_MAX_CONCURRENT_GENERATIONS` on a running worker.
  The live update route is `AdminUpdateSettings` in `src/OpenDeepWiki/Endpoints/Admin/AdminSettingsEndpoints.cs`.
</Callout>

## 增量更新

这些设置通过 `appsettings.json` 的 `IncrementalUpdate` 部分配置。它们控制检查仓库更新的后台工作者。

| 设置 | 默认值 | 描述 |
|---|---|---|
| `IncrementalUpdate:PollingIntervalSeconds` | `60` | 工作者检查待处理更新任务的频率（秒） |
| `IncrementalUpdate:DefaultUpdateIntervalMinutes` | `60` | 仓库更新检查之间的默认间隔（分钟） |
| `IncrementalUpdate:MinUpdateIntervalMinutes` | `5` | 允许的最小更新间隔（分钟） |
| `IncrementalUpdate:MaxRetryAttempts` | `3` | 失败更新的最大重试次数 |
| `IncrementalUpdate:RetryBaseDelayMs` | `1000` | 重试之间的基础延迟（毫秒），使用指数退避 |
| `IncrementalUpdate:ManualTriggerPriority` | `100` | 手动触发的更新任务的优先级值 |

## 仓库导入与存储

| 变量 | 必需 | 默认值 | 描述 |
|---|---|---|---|
| `REPOSITORIES_DIRECTORY` | 否 | `/data` | 用于存储克隆仓库文件的目录 |
| `RepositoryAnalyzer__AllowedLocalPathRoots__0` | 否 | — | 允许导入的本地目录根路径白名单（本地目录导入功能必需） |
| `RepositoryAnalyzer__LocalDirectoryImportMode` | 否 | `Copy` | 本地目录导入模式：`Copy`（复制）或 `Reference`（引用） |
| `RepositoryAnalyzer__CleanupAfterProcessing` | 否 | `false` | 处理完成后是否清理工作区 |

| 变量 | 必需 | 默认值 | 描述 |
|---|---|---|---|
| `MCP_ENABLED` | 否 | `true` | 是否启用 MCP 端点 |
| `MCP_STREAMABLE` | 否 | — | 为外部 AI 服务配置 MCP Streamable HTTP 端点。格式：`serviceName=url,serviceName2=url2` |

## Graphify 图谱产物（可选）

后端 Docker 镜像内置 `graphifyy` CLI。配置以下变量即可启用：

| 变量 | 描述 |
|---|---|
| `GRAPHIFY_BACKEND` | Graphify 后端类型 |
| `GRAPHIFY_MODEL` | Graphify 使用的模型 |
| `GRAPHIFY_OUTPUT_ROOT` | 产物输出目录（Docker 中默认 `/data/graphify-artifacts`） |
| `GRAPHIFY_OPENAI_BASE_URL` / `GRAPHIFY_OPENAI_API_KEY` | OpenAI 兼容凭证 |
| `OPENAI_BASE_URL` / `OPENAI_API_KEY`、`OLLAMA_BASE_URL` / `OLLAMA_MODEL` 等 | 各提供商回退凭证 |

## ASP.NET Core 运行时

| 变量 | 必需 | 默认值 | 描述 |
|---|---|---|---|
| `ASPNETCORE_ENVIRONMENT` | 否 | `Production` | 运行时环境：`Development`、`Staging`、`Production` |

## 前端（Web）

这些变量配置 Next.js 前端应用。

| 变量 | 必需 | 默认值 | 描述 |
|---|---|---|---|
| `NODE_ENV` | 否 | `production` | Node.js 环境模式 |
| `API_PROXY_URL` | 是 | `http://localhost:5265` | 前端代理的后端 API URL。在 Docker 中，使用服务名称：`http://opendeepwiki:8080` |
| `SITE_URL` | 否 | `http://localhost:8090` | 公开站点 URL，用于 sitemap、robots.txt、canonical URL 和社交分享元数据。生产环境应配置为实际访问域名 |
| `SITEMAP_REVALIDATE_SECONDS` | 否 | `3600` | sitemap 缓存 TTL（秒） |

## 示例：最小 `.env` 文件

```bash
# 数据库
DB_TYPE=sqlite
CONNECTION_STRING=Data Source=/data/opendeepwiki.db

# JWT（生产环境需更改！）
JWT_SECRET_KEY=replace-with-a-random-string-of-at-least-32-bytes

# AI 服务
CHAT_API_KEY=sk-your-api-key
ENDPOINT=https://api.openai.com/v1

# Wiki 生成
WIKI_CATALOG_MODEL=gpt-4o
WIKI_CATALOG_ENDPOINT=https://api.openai.com/v1
WIKI_CATALOG_API_KEY=sk-your-api-key
WIKI_CONTENT_MODEL=gpt-4o
WIKI_CONTENT_ENDPOINT=https://api.openai.com/v1
WIKI_CONTENT_API_KEY=sk-your-api-key

# 多语言
WIKI_LANGUAGES=en,vi
```

<Callout type="info">
  OpenDeepWiki 在启动时自动从当前目录或应用程序目录加载 `.env` 文件（`Program.cs` 中的 `LoadEnvFile`）。无需额外配置。
</Callout>
