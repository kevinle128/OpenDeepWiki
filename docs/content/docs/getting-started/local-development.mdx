# 本地开发

本指南将引导你为 OpenDeepWiki 设置本地开发环境。该项目由两部分组成：

- **后端** — ASP.NET Core API（`src/OpenDeepWiki/`）
- **前端** — Next.js 应用（`web/`）

## 前置条件

| 工具 | 版本 | 用途 |
|---|---|---|
| [.NET SDK](https://dotnet.microsoft.com/download) | 10.0+ | 后端构建和运行 |
| [Node.js](https://nodejs.org/) | 18+ | 前端构建和运行 |
| [Git](https://git-scm.com/) | 最新版 | 仓库克隆（后端运行时使用） |

<Callout type="info">
  后端目标是 `net10.0`。确保已安装 .NET 10 SDK。使用 `dotnet --version` 检查。
</Callout>

## 设置

<Steps>

<Step>
### 克隆仓库

```bash
git clone https://github.com/AIDotNet/OpenDeepWiki.git
cd OpenDeepWiki
```
</Step>

<Step>
### 配置后端

后端从 `appsettings.json` 和环境变量读取配置。对于本地开发，编辑 `src/OpenDeepWiki/appsettings.Development.json` 或设置环境变量：

```json title="src/OpenDeepWiki/appsettings.Development.json"
{
  "ConnectionStrings": {
    "Default": "Data Source=opendeepwiki.db"
  },
  "AI": {
    "Endpoint": "https://api.openai.com/v1",
    "ApiKey": "your-api-key"
  }
}
```

<Callout type="info">
  Development 环境不需要 `JWT_SECRET_KEY` 和 `DataProtection__KeyRingPath`。Production 环境需要：缺少它们，或 JWT 密钥短于 32 字节，应用启动失败并以退出码 1 结束。见[环境变量](/docs/configuration/environment-variables)。
</Callout>

你可能想设置的关键环境变量：

```bash
# AI 提供商配置
export CHAT_API_KEY=your-api-key
export ENDPOINT=https://api.openai.com/v1
export WIKI_CATALOG_MODEL=gpt-4o
export WIKI_CONTENT_MODEL=gpt-4o
export WIKI_CATALOG_API_KEY=your-api-key
export WIKI_CONTENT_API_KEY=your-api-key
```

默认情况下，后端使用 SQLite，数据库路径来自 `ConnectionStrings:Default`（容器内默认 `/data/opendeepwiki.db`，本地运行建议改为项目目录下的相对路径）。
</Step>

<Step>
### 启动后端

```bash
dotnet run --project src/OpenDeepWiki/OpenDeepWiki.csproj
```

API 默认在 `http` launch profile 下监听 `http://localhost:5265`（检查 `Properties/launchSettings.json` 获取确切端口）。开发环境下可通过 `/v1/scalar` 查看 OpenAPI 文档。
</Step>

<Step>
### 配置并启动前端

在另一个终端中：

```bash
cd web
npm install
```

创建或编辑 `web/.env.local` 以指向你的本地后端：

```bash title="web/.env.local"
API_PROXY_URL=http://localhost:5265
```

然后启动开发服务器：

```bash
npm run dev
```

前端在 [http://localhost:3000](http://localhost:3000) 启动。
</Step>

</Steps>

## 项目结构

```
OpenDeepWiki/
├── src/
│   ├── OpenDeepWiki/              # ASP.NET Core API（主入口）
│   │   ├── Endpoints/             # 最小 API 端点定义
│   │   ├── Services/              # 业务逻辑服务
│   │   ├── Agents/                # AI 代理和工具定义
│   │   ├── Chat/                  # 聊天系统（提供商、路由、队列）
│   │   ├── Models/                # 请求/响应 DTO
│   │   └── prompts/               # AI 提示模板（Markdown）
│   ├── OpenDeepWiki.Entities/     # 域实体和模型
│   ├── OpenDeepWiki.EFCore/       # 共享 EF Core DbContext
│   └── EFCore/
│       ├── OpenDeepWiki.Sqlite/   # SQLite 提供商
│       └── OpenDeepWiki.Postgresql/ # PostgreSQL 提供商
├── web/                           # Next.js 前端
│   ├── app/                       # App Router 页面
│   ├── components/                # React 组件
│   ├── hooks/                     # 自定义 React hooks
│   ├── lib/                       # API 客户端和工具
│   ├── e2e/                       # Playwright 端到端测试
│   └── i18n/                      # 国际化
├── tests/
│   ├── OpenDeepWiki.Tests/        # xUnit + FsCheck 测试
│   └── OpenDeepWiki.E2EHost/      # 端到端测试使用的后端宿主（假的 Git 提供商，临时 SQLite 数据库）
└── docs/                          # 本文档站点（Fumadocs）
```

## 运行测试

### 后端测试

```bash
dotnet test tests/OpenDeepWiki.Tests/OpenDeepWiki.Tests.csproj
```

### 前端测试与 lint

```bash
cd web
npm test                      # Vitest 单元测试
npx tsc --noEmit              # 类型检查
node scripts/check-i18n.js    # 检查所有语言文件与英文的键一致
npm run lint                  # ESLint 检查
```

<Callout type="warn">
  `npm run lint` 对整个 `web/` 目录仍会报告在本功能之前就存在的问题。共享仓库工作区的文件（`components/repositories`、`app/(main)/repositories`、`e2e`）应保持无 lint 问题。
</Callout>

### 后端工作流集成测试

`tests/OpenDeepWiki.Tests/Integration/GitConnectionWorkflowTests.cs` 在真实 SQLite 文件上，通过真实 HTTP 管线运行一条完整流程：创建连接、分页浏览目录、连接仓库并选择多个分支、添加和移除分支、禁用连接、权限检查。只有 Git 提供商是假的。

```bash
dotnet test tests/OpenDeepWiki.Tests/OpenDeepWiki.Tests.csproj --filter "FullyQualifiedName~GitConnectionWorkflowTests"
```

设置 `OPENDEEPWIKI_TEST_POSTGRES` 为一个一次性 PostgreSQL 服务器的连接字符串（例如 `Host=127.0.0.1;Port=55440;Username=postgres;Password=...;Database=postgres`），PostgreSQL 相关测试才会运行；否则它们被跳过。

### 端到端测试（Playwright，仅 Chromium）

端到端测试在真实浏览器中运行共享仓库工作区的主要流程：GitHub、GitLab.com 和自托管 GitLab 的连接、目录、分支，匿名/普通用户/创建者/管理员权限，以及响应式布局。它们不访问真实的 Git 提供商，也不使用真实令牌。

```bash
cd web
npm ci
npx playwright install chromium     # 首次运行，下载 Chromium
npm run test:e2e
```

需要 .NET 10 SDK。`npm run test:e2e` 自己启动并停止两个进程，使用固定端口：前端 `4310`，后端宿主 `4311`（`tests/OpenDeepWiki.E2EHost`，临时 SQLite 数据库和进程内的假提供商）。端口被占用时运行会直接停止，不会换端口。失败时的 trace 和截图保存在 `web/test-results`（在 CI 中另外生成 `web/playwright-report`），成功的运行不保留。`npm run test:e2e:ui` 打开 Playwright UI。

## 常见问题

### 后端构建失败

- 确保你有 .NET 10 SDK：`dotnet --list-sdks`
- 从仓库根目录运行 `dotnet restore` 以恢复 NuGet 包

### 前端无法连接到后端

- 验证后端正在运行并检查 `Properties/launchSettings.json` 中的端口（默认 `5265`）
- 确保 `web/.env.local` 中的 `API_PROXY_URL` 与后端 URL 匹配

### 数据库迁移错误

后端在启动时自动应用迁移。如果遇到问题，可以删除本地 SQLite 数据库文件并重启 — 它会被重新创建。
