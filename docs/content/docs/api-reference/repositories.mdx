# 仓库管理 API

OpenDeepWiki 提供一组 RESTful API 端点用于管理仓库，包括提交新仓库、查询仓库列表、更新可见性和重新生成文档。

基础路径：`/api/v1/repositories`

<Callout type="info">
大多数仓库管理端点需要用户认证。在 `Authorization` 头中包含有效的 JWT 令牌。
</Callout>

## Shared Git connections

A Git connection stores one GitHub or GitLab personal access token for one provider account. All signed-in users can
use a connection to browse the repositories of that account and to index them. Only the creator and an Admin can change
it. The workspace page `/repositories` uses these routes. A token is sent once, when the connection is created or
replaced, and no response contains it.

Every route needs `Authorization: Bearer <JWT>`. An anonymous request gets 401. Responses use one envelope:

```json
{ "success": true, "data": { } }
{ "success": false, "errorCode": "CONNECTION_DISABLED", "message": "The connection is disabled." }
```

The `message` text is fixed for each `errorCode`. It never contains provider text or a token. Use `errorCode` in code.

### Connections

Base path: `/api/v1/git-connections`

| Route | Who | Description |
|---|---|---|
| `GET /` | any user | List connections. Each item has `canMaintain` for the caller |
| `POST /` | any user | Create a connection. Body: `provider` (`GitHub` or `GitLab`), `token`, optional `displayName`, optional `serverUrl` (HTTPS origin of a self-hosted GitLab; empty means GitLab.com) |
| `GET /{id}` | any user | Read one connection |
| `PUT /{id}` | creator, Admin | Rename (`displayName`) or replace the token (`token`). An empty `token` keeps the current one |
| `DELETE /{id}` | creator, Admin | Soft delete. Returns 409 `CONNECTION_IN_USE` while a repository uses it |
| `POST /{id}/test` | creator, Admin | Health check. Provider failures are reported in the result (`ok`, `state`, `errorCode`, `latencyMs`, `checkedAt`) |
| `POST /{id}/enable`, `POST /{id}/disable` | creator, Admin | Enable or disable use of the connection |
| `GET /{id}/audit-events?limit=30` | creator, Admin | Newest first, `limit` up to 100 |

Create returns 201. If the provider account already has a connection, it returns 200 with `"existing": true` and the
existing connection. The existing token is not replaced: use `PUT` to replace it. Creating a connection for an account
whose connection was deleted restores that connection, and the caller becomes its creator. The new creator sees audit events only from the restore onward; an Admin still sees the full history.

A connection in the response has: `id`, `provider`, `displayName`, `serverUrl`, `accountLogin`, `repositoryCount`,
`state`, `isEnabled`, `lastValidatedAt`, `lastValidationErrorCode`, `createdAt`, `createdByUserId`, `canMaintain`, and
`hasSecret`. There is no token field.

### Catalog

| Route | Description |
|---|---|
| `GET /api/v1/git-connections/{id}/repositories?cursor=&pageSize=` | One page of the repositories that the token can see |
| `GET /api/v1/git-connections/{id}/repositories/{providerRepositoryId}/branches?cursor=&pageSize=` | One page of branches of a repository |

`pageSize` defaults to 50 and is capped at 100.
The result is `{ "items": [...], "nextCursor": "..." }`.
Pass `nextCursor` as `cursor` to get the next page.
The cursor is opaque and belongs to one connection.
`nextCursor` is `null` on the last page.
Add `q`, `visibility` (`all`, `public`, or `private`), or `sort` (`updated`, `updatedAsc`, or `name`) to query the catalog.
For GitLab, the server sends these filters to the Projects API and reads only the requested page.
GitLab queries shorter than three Unicode characters use local substring matching over sorted provider pages because GitLab uses exact matching for short queries.
For short queries, the server skips empty pages and returns the first page with matches, which can contain fewer than `pageSize` items.
Continue with `nextCursor` to search later provider pages; `totalCount` is `null` for short queries.
Each short-query request can skip at most 100 empty pages and returns `PROVIDER_REQUEST_REJECTED` if that limit is reached.
GitLab search uses the provider's matching rules for project names, paths, descriptions, and namespaces.
GitLab name sorting uses the project name, and update sorting uses the last activity time.
The GitLab `private` filter selects private projects; internal projects appear with `all`.
`totalCount` comes from GitLab's `X-Total` header and can be `null` when the provider omits it.
For GitHub, the server reads all accessible provider pages before filtering, sorting, and returning a result page with `totalCount`.
Search text is limited to 200 characters.
Catalog cursors are bound to the search, visibility, sort order, and connection.
GitLab catalog cursors are also bound to the page size.
Reset the cursor when filters change.
The GitHub catalog reads at most 100 provider pages per request and returns `PROVIDER_REQUEST_REJECTED` instead of a partial catalog when that limit is exceeded.

A repository item has `providerRepositoryId`, `name`, `fullName`, `namespace`, `description`, `cloneUrl`, `webUrl`,
`defaultBranch`, `visibility`, and `updatedAt`. A branch item has `name`, `isDefault`, and `commitSha`.
`providerRepositoryId` is the numeric ID of the provider. It does not change when the repository is renamed.

The catalog is not available for a disabled connection (409 `CONNECTION_DISABLED`).

### Connect a repository and manage its branches

```
POST /api/v1/connected-repositories
```

| Field | Type | Required | Description |
|---|---|---|---|
| `connectionId` | string | yes | Connection to use |
| `providerRepositoryId` | string | yes | ID from the catalog |
| `branches` | string[] | yes | Branches to index (at least 1, at most 50) |
| `languageCode` | string | no | Documentation language |
| `generateSkill` | boolean | no | Create the SKILL package. Default `true`. Used only when the request creates the repository |

The service checks every branch against the provider, then creates the repository record (if it does not exist) and one
independent full-generation task for each new branch. The result has `repositoryId`, `orgName`, `repoName`,
`gitConnectionId`, `repositoryCreated`, and `branches[]` with `branchId`, `branchName`, `created`, `taskId`, and
`taskStatus`. The status is 201 when something was created, and 200 when the request found only existing data. A repeated
request creates nothing new.

| Route | Description |
|---|---|
| `GET /api/v1/repositories/{repositoryId}/indexed-branches` | Branches with `generationStatus`, `lastCommitId`, `languages`, `activeTaskId`, and `activeTaskKind` |
| `POST /api/v1/repositories/{repositoryId}/indexed-branches` | Add branches: body `{ "branches": ["dev"], "languageCode": "en" }`. Same result shape as connect |
| `DELETE /api/v1/repositories/{repositoryId}/indexed-branches/{branchId}` | Remove one branch with its documents, tasks, and workspace. Other branches are not changed |
| `POST /api/v1/repositories/{repositoryId}/branches/{branchId}/generation-tasks/full` | Rebuild one branch |
| `GET /api/v1/repositories/{repositoryId}/branch-generation-tasks` | List generation tasks |
| `GET /api/v1/branch-generation-tasks/{taskId}`, `POST .../retry`, `POST .../cancel` | Read, retry, or cancel one task |
| `POST /api/v1/repositories/{repositoryId}/branches/{branchId}/incremental-update` | Start a sync of one branch. See [Incremental updates](/docs/api-reference/incremental-updates) |

Any signed-in user can manage branches of a connected repository, including a private repository, in the shared workspace.
Private legacy repositories without a shared connection remain limited to their owner and an Admin.
Deleting a repository and changing its visibility keep their own rules and are not part of these routes.

### Error codes

| Status | `errorCode` | Meaning |
|---|---|---|
| 400 | `INVALID_PROVIDER`, `INVALID_TOKEN`, `INVALID_DISPLAY_NAME`, `INVALID_REQUEST` | The request is not valid |
| 400 | `SERVER_URL_INVALID`, `SERVER_URL_BLOCKED` | The GitLab server URL is not an HTTPS origin, or its address is not allowed |
| 400 | `INVALID_CURSOR`, `INVALID_REPOSITORY_ID`, `NO_BRANCHES_SELECTED`, `TOO_MANY_BRANCHES`, `INVALID_BRANCH_NAME` | The request is not valid |
| 401 | `UNAUTHORIZED` | Not signed in |
| 403 | `CONNECTION_MAINTENANCE_FORBIDDEN` | Only the creator or an Admin can change the connection |
| 404 | `CONNECTION_NOT_FOUND`, `REPOSITORY_NOT_FOUND`, `BRANCH_NOT_FOUND`, `PROVIDER_NOT_FOUND` | The item does not exist, or the caller cannot see it |
| 409 | `CONNECTION_DISABLED` | The connection is disabled. Existing documentation stays readable |
| 409 | `CONNECTION_IN_USE`, `CONNECTION_CONFLICT`, `CONNECTION_ACCOUNT_MISMATCH`, `CONNECTION_SECRET_UNREADABLE` | Delete with repositories, concurrent change, token of another account, token that cannot be decrypted (replace it) |
| 409 | `BRANCH_JOB_ACTIVE` | A job of this branch is processing. The branch is not removed |
| 409 | `GENERATION_LOCK_CONFLICT`, `REPOSITORY_GENERATION_ACTIVE`, `REPOSITORY_ALREADY_CONNECTED`, `REPOSITORY_NOT_CONNECTED` | Generation is running, the repository already uses another connection (a manual connect never changes it; only the legacy migration links an existing repository), or it has no connection |
| 422 | `PROVIDER_UNAUTHORIZED`, `PROVIDER_FORBIDDEN` | The provider rejected the token, or the token has no permission. This is 422 and not 401, because the web client signs the user out on any 401 |
| 422 | `REMOTE_BRANCH_NOT_FOUND`, `REMOTE_BRANCH_LOOKUP_LIMIT` | A selected branch does not exist on the remote (the response lists the names in `branches`), or the remote has too many branches to check |
| 429 | `PROVIDER_RATE_LIMITED` | Provider rate limit. The `Retry-After` header holds the seconds to wait |
| 504 | `PROVIDER_TIMEOUT` | The provider did not answer in time |
| 502 | `PROVIDER_UNAVAILABLE`, `PROVIDER_DNS_FAILURE`, `PROVIDER_TLS_FAILURE`, `PROVIDER_REDIRECT_BLOCKED`, `PROVIDER_INVALID_RESPONSE`, `PROVIDER_REQUEST_REJECTED`, `REMOTE_INVALID` | The provider request failed |

### Behavior that is not part of this API

- There is no per-repository automatic synchronisation setting. Use the sync route to update one branch.
- There is no Gitee connection type. A Gitee repository keeps its legacy credential, and Gitee requests are sent without a token.
- The catalog has no field that says whether a repository is already indexed.

## 提交仓库

提交新仓库用于文档生成。

```
POST /api/v1/repositories/submit
```

### 请求体

| 字段 | 类型 | 必需 | 描述 |
|---|---|---|---|
| `gitUrl` | string | 是 | Git 仓库 URL（最多 500 字符） |
| `repoName` | string | 是 | 仓库名称（最多 100 字符） |
| `orgName` | string | 是 | 组织/所有者名称（最多 100 字符） |
| `branchName` | string | 是 | 要处理的分支（最多 200 字符） |
| `languageCode` | string | 是 | 文档生成的语言代码（最多 50 字符），例如 `en`、`zh-CN` |
| `isPublic` | boolean | 否 | 仓库是否公开（默认：`true`） |
| `gitConnectionId` | string | 私有仓库需要 | 共享 Git 连接的 ID（最多 36 字符）。连接必须存在、已启用，并且与 `gitUrl` 属于同一个 Git 服务器 |
| `authAccount` | string | — | 已不再接受。发送它返回 400 `LEGACY_CREDENTIAL_FIELDS_REJECTED`，请改用 `gitConnectionId` |
| `authPassword` | string | — | 已不再接受，同上 |

### 示例请求

```json
{
  "gitUrl": "https://github.com/AIDotNet/OpenDeepWiki",
  "repoName": "OpenDeepWiki",
  "orgName": "AIDotNet",
  "branchName": "main",
  "languageCode": "en",
  "isPublic": true
}
```

### 响应

成功时返回创建的 `Repository` 对象。

```json
{
  "id": "a1b2c3d4-...",
  "gitUrl": "https://github.com/AIDotNet/OpenDeepWiki",
  "repoName": "OpenDeepWiki",
  "orgName": "AIDotNet",
  "isPublic": true,
  "status": "Pending"
}
```

### 错误响应

| 状态 | 描述 |
|---|---|
| 401 | 用户未认证 |
| 400 | 当 `isPublic` 为 `false` 时需要凭证 |
| 400 `LEGACY_CREDENTIAL_FIELDS_REJECTED` | 请求带有 `authAccount` 或 `authPassword`。创建 Git 连接，并发送 `gitConnectionId` |
| 400 `GIT_URL_CONTAINS_CREDENTIALS` | `gitUrl` 含用户名或令牌 |
| 400 `CONNECTION_NOT_FOUND`、`CONNECTION_DISABLED`、`CONNECTION_HOST_MISMATCH` | 连接不存在或不可用，或属于另一个 Git 服务器 |

这些 400 响应的格式是 `{ "success": false, "errorCode": "...", "message": "..." }`。

## 列表仓库

检索带有过滤和排序的分页仓库列表。

```
GET /api/v1/repositories/list
```

### 查询参数

| 参数 | 类型 | 默认值 | 描述 |
|---|---|---|---|
| `page` | int | `1` | 页码 |
| `pageSize` | int | `20` | 每页项数 |
| `isPublic` | bool | — | 按可见性过滤 |
| `keyword` | string | — | 按组织名或仓库名搜索 |
| `language` | string | — | 按主要编程语言过滤 |
| `ownerId` | string | — | 按所有者用户 ID 过滤 |
| `status` | int | — | 按处理状态过滤 |
| `sortBy` | string | `createdAt` | 排序字段：`createdAt`、`updatedAt`、`status` |
| `sortOrder` | string | `desc` | 排序方向：`asc` 或 `desc` |

### 示例请求

```
GET /api/v1/repositories/list?page=1&pageSize=10&isPublic=true&keyword=opendeep
```

### 响应

```json
{
  "items": [
    {
      "id": "a1b2c3d4-...",
      "orgName": "AIDotNet",
      "repoName": "OpenDeepWiki",
      "gitUrl": "https://github.com/AIDotNet/OpenDeepWiki",
      "status": "Completed",
      "statusName": "Completed",
      "isPublic": true,
      "hasPassword": false,
      "hasGitConnection": false,
      "gitConnectionId": null,
      "createdAt": "2025-01-15T10:30:00Z",
      "updatedAt": "2025-01-15T12:00:00Z",
      "starCount": 1200,
      "forkCount": 150,
      "primaryLanguage": "C#"
    }
  ],
  "total": 42
}
```

### 仓库状态值

| 值 | 名称 | 描述 |
|---|---|---|
| 0 | Pending | 等待处理 |
| 1 | Processing | 正在生成文档 |
| 2 | Completed | 文档生成完成 |
| 3 | Failed | 文档生成失败 |

## 更新可见性

更改仓库的公开/私有可见性。

```
POST /api/v1/repositories/visibility
```

### 请求体

| 字段 | 类型 | 必需 | 描述 |
|---|---|---|---|
| `repositoryId` | string | 是 | 仓库 ID（最多 36 字符） |
| `isPublic` | boolean | 是 | 新的可见性设置 |

### 示例请求

```json
{
  "repositoryId": "a1b2c3d4-...",
  "isPublic": false
}
```

### 响应

```json
{
  "id": "a1b2c3d4-...",
  "isPublic": false,
  "success": true,
  "errorMessage": null
}
```

### 错误响应

| 状态 | 描述 |
|---|---|
| 401 | 用户未认证 |
| 403 | 无权修改此仓库 |
| 404 | 仓库未找到 |
| 400 | 未配置凭证时无法设置为私有 |

## 重新生成文档

重新生成仓库的文档。仅在仓库状态为 `Completed` 或 `Failed` 时可用。

```
POST /api/v1/repositories/regenerate
```

### 请求体

| 字段 | 类型 | 必需 | 描述 |
|---|---|---|---|
| `owner` | string | 是 | 仓库所有者/组织名称（最多 100 字符） |
| `repo` | string | 是 | 仓库名称（最多 100 字符） |

### 示例请求

```json
{
  "owner": "AIDotNet",
  "repo": "OpenDeepWiki"
}
```

### 响应

```json
{
  "success": true,
  "errorMessage": null
}
```

### 错误响应

| 条件 | `errorMessage` |
|---|---|
| 用户未认证 | "用户未登录" |
| 仓库未找到 | "仓库不存在" |
| 无权限 | "无权限操作此仓库" |
| 仓库正在处理 | "仓库正在处理中，无法重新生成" |

<Callout type="warn">
重新生成会清除所有现有文档（目录、文档文件、处理日志）并将仓库状态重置为 `Pending`。后台工作者将自动选择它进行重新处理。
</Callout>

## 获取分支

从远程平台检索 Git 仓库的可用分支列表。

```
GET /api/v1/repositories/branches?gitUrl={gitUrl}
```

### 查询参数

| 参数 | 类型 | 必需 | 描述 |
|---|---|---|---|
| `gitUrl` | string | 是 | Git 仓库 URL |

### 响应

```json
{
  "branches": [
    { "name": "main", "isDefault": true },
    { "name": "develop", "isDefault": false }
  ],
  "defaultBranch": "main",
  "isSupported": true
}
```

<Callout type="info">
`isSupported` 表示 Git 平台是否支持通过 API 列出分支。支持的平台包括 GitHub、GitLab、Gitee 等。此路由现在需要登录（未认证返回 401）。对 Gitee 的请求不带令牌。对已连接的仓库，请使用上面的连接目录路由列出分支。
</Callout>
